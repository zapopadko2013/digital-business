# Digital Business Card API

Backend-сервис для платформы цифровых визиток, построенный на базе **NestJS**, **GraphQL** (Code-First) и **Prisma ORM** с использованием **PostgreSQL** и **Docker**.

## Стек технологий

- **Framework:** NestJS
- **API:** GraphQL (Apollo Server, подход Code-First с автогенерацией `schema.gql`)
- **Database:** PostgreSQL
- **ORM:** Prisma
- **Infrastructure:** Docker, Docker Compose


---

## Архитектура базы данных (Prisma Schema)

В основе платформы лежит реляционная база данных PostgreSQL. Схема спроектирована так, чтобы гибко связывать личную информацию пользователя с его карьерой, навыками и публичными профилями.

### Основные сущности:

1. **Person (Пользователь / Сотрудник)**
   - Центральная сущность, хранящая базовые персональные данные (Имя, Фамилия, уникальный Email).
   - К ней привязаны все остальные профессиональные достижения человека.

2. **Company (Компания)**
   - Справочник компаний, где работал или работает пользователь (название, веб-сайт).
   - Используется для структурирования опыта работы и проектов.

3. **Profile (Цифровая визитка)**
   - Публичная страница пользователя. У каждого человека может быть несколько визиток (например, под разные направления: Backend, Frontend, DevOps) с уникальной ссылкой (`slug`), описанием и списком ссылок на соцсети.

4. **Skill (Навыки)**
   - Профессиональные умения сотрудника с возможностью деления на категории.

5. **Experience (Опыт работы)**
   - Информация о занимаемой должности, периоде работы, компании и ключевых достижениях (массив строк).

6. **Project (Проекты)**
   - Портфолио проектов пользователя с указанием ссылки и опциональной привязкой к компании.

### Особенности связей и целостности данных:

- **UUID в качестве ID:** Все таблицы используют глобально уникальные идентификаторы (`uuid`), что повышает безопасность и масштабируемость системы.
- **Каскадное удаление (`onDelete: Cascade`):** Если профиль, навык, опыт работы или проект принадлежат конкретному пользователю (`Person`), то при удалении пользователя эти данные автоматически удаляются из базы.
- **Защита связанных данных (`onDelete: Restrict` / `SetNull`):**
  - Компанию (`Company`) нельзя удалить, если на неё ссылается действующий опыт работы (защита от случайной потери данных).
  - При удалении компании из проекта связь просто очищается (`SetNull`), сохраняя сам проект в портфолио.
